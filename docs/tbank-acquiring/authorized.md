# AUTHORIZED у Т‑Банка — не «оплачено»

Ответ скопирован из кабинета / отладчика (вложенные `Key` / `Value`). Это интернет-эквайринг Т‑Банка (EACQ), метод вроде `GetState` или нотификация.

## Исходный дамп

```
Success: true
ErrorCode: "0"
Message: "OK"
TerminalKey: "1579864014451"
Status: "AUTHORIZED"
PaymentId: "9167107039"
OrderId: "49332682"
Params:
  0: Key: "Route"  Value: "ACQ"
  1: Key: "Source" Value: "cards"
Amount: 90000
```

Нормализованный JSON: [payment-9167107039.json](payment-9167107039.json). Разобрать такой текст: `python3 parse_payment.py dump.txt`.

## Что уже произошло

Покупатель картой прошёл авторизацию. Банк **заблокировал 900 ₽** на карте. Терминал `1579864014451`, маршрут `ACQ` + `cards` — классический карточный эквайринг.

`Success` / `ErrorCode: "0"` / `Message: "OK"` относятся к **вызову API**, не к финальному списанию.

## Чего ещё нет

На двухстадийной схеме успешная оплата для мерчанта — статус **`CONFIRMED`**.

| Статус | Деньги | Заказ |
| --- | --- | --- |
| `AUTHORIZED` | Холд на карте | Ещё не оплачен |
| `CONFIRMED` | Списаны на расчётный счёт (по регламенту банка) | Можно закрывать как оплаченный |
| `CANCELED` / `REVERSED` | Холд снят | Не оплачен |
| `REJECTED` / `AUTH_FAIL` / `DEADLINE_EXPIRED` | Списания нет | Не оплачен |
| `REFUNDED` | Возврат после списания | Был оплачен, потом вернули |

`AUTHORIZED` бывает **только** на двухстадийном платеже (`PayType=T`). На одностадийном после успеха сразу `CONFIRMED`.

## Что вызывать дальше

Документация Т‑Банка: [Confirm](https://developer.tbank.ru/eacq/api/confirm) — только для статуса `AUTHORIZED`.

- Списать 900 ₽ целиком: `POST /v2/Confirm` с `TerminalKey`, `PaymentId=9167107039`, подпись `Token`. `Amount` можно не передавать.
- Списать меньше: передать `Amount` в копейках, не больше 90000. Остаток холда банк отпускает.
- Отменить: `POST /v2/Cancel` с тем же `PaymentId`.

Пока холд жив, повторный `Init` на тот же `OrderId` часто даёт ошибку «заказ уже существует». Сначала Confirm или Cancel, потом новый платёж.

Срок холда задаётся в договоре/терминале (обычно несколько суток). После дедлайна статус `DEADLINE_EXPIRED`, Confirm уже не сработает.

## Как не перепутать в 1С / на кассе

- Нотификация с `AUTHORIZED` — **не** проводить реализацию и **не** закрывать чек как безнал «оплачено», если схема двухстадийная.
- Проводить оплату по нотификации / `GetState` со статусом `CONFIRMED`.
- `Amount` всегда в **копейках**. `90000` — это 900 рублей, не 90 000.
- `Route=ACQ` и `Source=cards` не требуют отдельной обработки СБП (`SBP`) или счета (`EINV`).

## Чего делать не надо

- Не считать `Message: "OK"` финальной оплатой.
- Не вызывать `FinishAuthorize` на уже `AUTHORIZED` карточный платёж — это шаг 3‑D Secure / Apple Pay / Google Pay **до** авторизации.
- Не публиковать пароль терминала и `Token`. `TerminalKey` и `PaymentId` — идентификаторы, не секрет подписи.
